# P1.8 — Declared Simulation Profile (`binding-context/3`)

Additive to P1.6. Describes simulations, method return types and evaluation
records in the Cube domain **without executing anything**. See
`P1_8_ACCEPTANCE_SPEC.md` (decisions resolved in §6).

Every source file (preregistration, simulator, metrics, scenario, evaluator, oracle, expected result, data) is pinned by SHA-256 to the `lunados.space` repository:

```bash
python3 P1/simulation-profile-v1/scripts/build_goldens.py --space ~/SitesHeroku/lunados.space --verify
```

A golden PASS states only that the archived experiment is *declared* well-formed in the Cube domain: method, closed world, evaluator, record and witness pointer. The archived numbers and the dominance relation are recorded in `reference.declared_finding` and are never recomputed. Seven negative controls in `tests/test_p18.py` (class `Golden`) show that the cases are not trivially passing. Two adjustments are disclosed in each file: `decision.compare/v0.1` becomes `decision.compare/v1` (P1 method-ID rule), and EXP-010 has no `library_ref` because no Functions Library entry exists for it.

## Supersession of Charge 3 (expected, not a regression)

Charge 3 froze `p1_adapter.py`, `core_runtime.py` and `assemble_core.py` by SHA-256
(`P3/charge3-p16/CHARGE3_SOURCE_SHA256SUMS.txt`). P1.8 must change them, so
Charge 3 source verification no longer matches HEAD. Run it against commit
`9954c1d` instead. Charge 3 `test_08_never_accept_unknown_context_format`
assumes `/3` is unknown. With P1.8 it is a known, explicitly activated format.
The intent (no implicit format upgrade) still holds for any other format.
`gateway/src/index.mjs` is intentionally unchanged, so the Charge 3 freeze
anchor stays valid. The MCP `serverInfo.version` therefore still reads
`0.1.0-proof`, while `cube_discover_surface` reports `0.2.0-proof`.
A Charge 4 freeze for P1.8 is the follow-up.
