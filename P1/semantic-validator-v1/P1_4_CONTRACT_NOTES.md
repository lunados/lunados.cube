# P1.4 — Scope boundaries and semantic decisions

1. **Authority:** v9.4 remains the semantic reference; P1-VC/1.0.0 remains a separately scoped engineering validation profile. P1.2 and P1.3 implementation snapshots are reused unchanged. No P0 file is modified.
2. **Predicate names ≠ typed signatures.** Match `(predicate_id, scope_ref)` exactly; a single match is required; multiple matches cannot be arbitrarily selected by revision. Direction is *only* `subject_to_object`. No predicate implicit inversion, symmetry, or path composition. Subexpressions other than references have no known output concept type.
3. **Predicate typing:** enforce caller-declared allowed subject/object concept IDs and relation-level `required_qualifiers`. The P1.1 predicate contract does not provide a typed keyword parameter spec: a relation with nonempty parameters is `UNRESOLVED` at predicate stage.
4. **Method typing:** select one scoped method declaration; enforce argument cardinality/order/exact concepts, only `pure_declarative` is eligible for descriptive `PASS`. `effectful_declared` application `FAIL` (no effects are attempted), unknown purity `UNRESOLVED`. Nested application return types and untyped keyword parameters remain unresolved. `revision` is required in context but not authenticated by AST text.
5. **T:** the eight v9.4 facet labels are the entire known built-in role set. Unknown role `FAIL` (`P1_TEMPORAL_ROLE`); missing witness/profile `UNRESOLVED`. No inference from timestamp ordering to causality.
6. **O:** availability, permission, delivery, perception, and conclusion are not interchangeable. The bare `delivered=true`, `permitted=true`, or `actor_ref` parameters cannot validate themselves. An explicit untrusted witness pointer can support **fixture-scoped shape PASS only**.
7. **M:** the mode names Loose/Transitional/Strict are never production enumerations. A separately declared local **presentation-only** profile can type such a label but confers no operating authorization.
8. **F:** an F method identifier must have a declared matching scoped method profile with `pure_declarative` effect class, along with a separately supplied local qualification profile.
9. **Qualifier profile extension:** P1.1's `context.schema.json` is not revised; the P1.4 optional `qualification-profiles/1` is a separate file and separately versioned local engineering contract. T/O require declared witness pointers. The extension adds `P1_QUALIFIER_SIGNATURE` to diagnostics as documented in `DIAGNOSTIC_EXTENSION.json` (P1.5 must review this addition).
10. **Scope:** no implicit borrowing of signatures from another scope. Explicit mismatch -> `FAIL`; missing scope -> `UNRESOLVED`. A caller's declared `scope_ref` is never an authenticated grant. No real Authority, Admission or canonical Thread effect is checked.
11. **Result:** deterministic, JSON-schema-compatible 8-stage report. `FAIL > UNRESOLVED > PASS`; inapplicable `NOT_EVALUATED` excluded. Diagnostic order stable by byte position (if available), code, stage, message/path. For semantic diagnostics without a source span, the AST path is embedded in the message.
12. **Conformance limits:** P1.4's executable tests confirm its **declared profile**, not universal validity of arbitrary foreign instances, mathematical theorems, empirical claims or production tooling. Formal verification and source-code-independent oracle belong to P1.5.
